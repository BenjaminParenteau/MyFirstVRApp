# Security office

The existing `MVP_SecurityOffice` shell, approach hall and door IDs are preserved. The furnished office is CPU-baked with the shared lighting settings. `SecurityOffice_Operations` under `RoomA (Security Office)` owns the new furnishings. Rebuild with **High Stakes > Security > Build Furnished Security Office**. Do not rebuild all security wings to install this room: that discards scene edits. If the wing generator is run later, run the office furnishing pass again.

Six physical monitors show the casino floor, VIP lounge, staff hall, vault room/approach, cashier side and VIP tables. `SecurityMonitorWall` loads the four actual source scenes additively with isolated physics; no exported room replicas or prerecorded video. Remote doors, table gameplay, pickups, audio and realtime lights are disabled before their first update. Existing patrols and animators continue. `_SoloTest` stays disabled, leaving the one player rig and wallet in `MVP_Main`. CCTV cameras are mono, untagged, have no AudioListener and only render into textures.

Capture uses Unity URP's `SingleCameraRequest`, one camera and one channel per update, at 512 x 288 / four updates per second per feed. Rendering stops outside the office's viewing distance. Layers 26–29 are reserved dynamically for remote rooms and excluded from the player camera; no project layer configuration is changed. SceneFlow waits for CCTV source scenes to unload before loading the next playable area, then restores the player camera's mask. Press the cyan **LIVE / HOLD** button with an XR ray or direct selection to freeze/resume the wall.

Desks are 0.75 m high; seats 0.45 m. The 2 m entrance and centre route remain clear. Equipment, monitors, lockers, storage, radios, telephone, report desk, duty board, cable trays and fluorescent housings use existing kit materials or Simple Lit material variants. Furnishing geometry is combined by material. Added fixtures are emissive; no new realtime lights, shadows, post effects, rigs, NPCs, suspicion logic, vault-code clues or rewards are introduced.

Run **High Stakes > Security > Run Office Live Feed Play Check** for real scene-load, render-target, hold/resume, single-rig/wallet and office/hub/revisit checks. It writes a report and render previews to `Temp/SecurityOfficeQA` and leaves the office open afterwards. Start `MVP_Main` for normal gameplay; the approach hallway's existing portal leads into the actual office at x=40. Live images start in Play mode. Editor screens use previews captured by the last Play check; refresh them using **High Stakes > Security > Use Last Play Check as Editor Screen Previews**. The style check excludes the unchanged solo test rig, whose built-in ray materials are outside the content folder.

Quest 3 APK profiling is still required: loading four remote areas retains their assets in memory even when capture rendering pauses. The 72 fps target is not established by editor checks. Future remote gameplay systems must opt into observation deliberately; CCTV currently observes geometry and existing animation, with interactions dormant.
